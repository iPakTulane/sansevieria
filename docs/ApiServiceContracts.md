# API Service Contracts

This document summarizes the formal service contracts implicitly generated by the Sansevieria FastAPI backend. These contracts govern how the frontend, external system integrators, and internal services interact with the domain model consistently.

## 1. OpenAPI Standards
All HTTP endpoints are strongly parameterized via Pydantic classes and standard Python type hints. 
- Fast API automatically translates these structures natively into an interactive **OpenAPI 3.0** specification.
- A fully interactive Swagger UI is generated natively (available by default at `/docs`), offering live schemas, required structural validation rules, and built-in interactive execution testing natively.

## 2. Key Endpoint Map

The core routing structure separates cleanly into logical domain bundles:
- **Authentication**: `POST /api/auth/register`, `POST /api/auth/login`
- **Products**: `GET /api/products`, `GET /api/products/{id}`, `POST /api/products` *(Cache Invalidation Mock)*
- **Cart Tracking**: `GET /api/cart`, `POST /api/cart`
- **Orders & Operations**: `GET /api/orders`, `GET /api/orders/{id}`, `POST /api/checkout`

## 3. Request / Response Structures & Example Schemas

Every data flow in and out of the API is rigorously enforced by Pydantic models. Any payload that deviates implicitly from the defined structure is natively rejected with a `422 Unprocessable Entity` without ever executing business controllers natively.

### 3.1. Authentication Contracts

**`POST /api/auth/register`**
- **Incoming Request** (`UserCreate`): Defines the creation parameters explicitly dropping into the DB.
  ```json
  {
      "email": "user@example.com",
      "password": "SecurePassword123!",
      "full_name": "Sansevieria Enthusiast"
  }
  ```
- **Outgoing Response** (`UserResponse`): Securely strips the hashed password before explicitly returning the native tracking UUID locally to the caller natively.
  ```json
  {
      "id": 1,
      "email": "user@example.com",
      "full_name": "Sansevieria Enthusiast",
      "is_active": true
  }
  ```

**`POST /api/auth/login`**
- **Incoming Request** (`OAuth2PasswordRequestForm`): A standard `x-www-form-urlencoded` spec.
- **Outgoing Response** (`Token`): JWT strings explicitly mapping access spans natively.
  ```json
  {
      "access_token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
      "token_type": "bearer"
  }
  ```

### 3.2. E-Commerce Flow Contracts

**`GET /api/products`** (Cache Hit Accelerated)
- **Response** (`List[ProductResponse]`): A native JSON array fetching current mapped product inventory globally.
  ```json
  [
    {
        "id": 1,
        "name": "Snake Plant Laurentii",
        "description": "A hardy, low-maintenance houseplant.",
        "price": 24.99,
        "image_url": "/images/laurentii.jpg",
        "stock": 150
    }
  ]
  ```

**`POST /api/checkout`**
This endpoint highlights the transition from synchronous REST into asynchronous workflow processing!
- **Auth**: Requires a valid Bearer Token securely passing User metadata into execution seamlessly.
- **Response** (`OrderResponse`): Notice how the `status` natively returns `PENDING`. This definitively signals that the API is fully acknowledging the input natively, but the user must poll or wait for asynchronous RabbitMQ orchestration to handle the `COMPLETED` finalization dynamically later!
  ```json
  {
      "order_id": "ORD-085739",
      "user_id": 1,
      "total_amount": 74.97,
      "status": "PENDING"
  }
  ```
